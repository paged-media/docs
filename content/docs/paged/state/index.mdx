**In short:** paged tracks every capability as one row in a **registry**. Each row
says which layers implement it, and the newest CI test runs of every repository
decide whether it is healthy. These pages render that record, rebuilt every night
and whenever a repository's tests finish, so anyone can see where the system
stands.

<StatusHeadline />

## Where to look

- **[Capability matrix](/docs/paged/state/matrix)** — every capability across
  every layer (parser, renderer, mutation, editor, plugins), with a status and a
  test-health glyph per cell.
- **[How it works](/docs/paged/state/how-it-works)** — the registry, where its
  test evidence comes from, and what keeps these pages from going stale.

A claim with no linked test shows as **untested**, and a claim whose tests passed
before its latest code change shows as **re-test pending**. Only a passing test
run newer than the change shows as verified.

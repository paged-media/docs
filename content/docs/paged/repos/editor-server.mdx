**In short:** paged.server is the optional remote behind the
[editor](/docs/paged/repos/editor). It lives at `apps/server` in the public
[`paged-media/paged`](https://github.com/paged-media/paged/tree/main/apps/server)
repository and is <Fact id="license.server" />. It replaces the TypeScript
`editor-server` (a separate repository, now archived), which this page described
until the monorepo.

## What it does

The editor works without a server: a document is a repository in the browser, with
its history, branches and releases. paged.server adds what needs a remote:

- **Sync** — push and pull of document repositories.
- **Sharing** — workspaces, members, roles and change requests.
- **An MCP endpoint** — a connector an assistant reaches over OAuth.
- **A live relay** — calls from that connector to an editor tab that is open.

It holds no format knowledge of its own: the repository format is the engine's
`paged-repo` crate, the same code the browser and the command line run.

## How it's organized

A Rust workspace (`apps/server/server`) built for Cloudflare Workers: one Worker
for routing, sign-in and the sync and MCP endpoints, Durable Objects for each
repository, workspace and live session, and an object bucket for large blobs. Its
decision records are in `apps/server/docs/adr`.

## Its HTTP API

The editor-server's REST API was generated from its OpenAPI specification.
paged.server publishes no OpenAPI specification yet, so the
[REST API page](/docs/paged/api/rest) has no endpoints to list until it does.

**In short:** you're reading it. `docs` is a public Fumadocs (Next.js App Router +
MDX) app built as two sites: the **[IDML Reference](/docs/idml/overview)** (the
format) at idml.paged.media and the Paged docs (the system) at docs.paged.media.
Each is a static export deployed to Cloudflare Pages.

## How it stays current

The platform pages and the IDML support badges are **generated from the system's
own sources** at build time — the capability record of the
[registry](/docs/paged/repos/cockpit) (with the test health of every capability),
the engine [scripting catalog](/docs/paged/scripting), the plugin registries,
each package's licence, the
[plugin manifest schema](/docs/paged/plugin-sdk), the server
[OpenAPI spec](/docs/paged/api), and the repos' commit history. A pin file
records the sources; a nightly rebuild and on-push triggers keep it fresh; and a
freshness gate flags authored prose whose capabilities' code has moved; the build
fails a page that types a platform number by hand (`<Fact>` renders it), a
comparison score whose capabilities are not verified, and a capability record
more than a week old. The design rule:
*a page is either generated or guarded — never just hoped-to-be-current.*

## How it consumes the engine

The IDML examples are validated in CI against the real renderer (`paged-inspect`
built from a pinned core release), and the live preview embeds the published
[viewer](/docs/paged/repos/viewer). The clean-room rule governs the IDML
reference prose.

**Can Paged do the jobs a team runs on Adobe InDesign Server?**

**In short:** many of them, and in the open. Paged's engine runs without a desktop
application: the `paged` command line and its HTTP engine service open IDML, run
JavaScript against the document, merge records into a template and write PDF/X-4,
IDML, `.paged` and PNG. It is one program you build or install, with no seat or
licence server in the loop. Some jobs are not covered yet: it does not read `.indd`
files, it does not run ExtendScript, and Data Merge from the command line needs a
source checkout. The table below says which job is which, with each status read
from the [capability record](/docs/paged/state/matrix).

## The jobs, one by one

planned, and whether its tests pass). A row without a badge is one the record does not
track, and its status is said in words.

## Worked example: a template and a CSV to PDF/X-4

The commands below were run against the engine built from the main branch after
v0.74.2. They make a three-field price card, merge three records into it and export
print PDF.

### 1. Build the tools

```bash
# The Rust command line, from a checkout of paged-media/paged
cd engine/core && cargo build --release -p paged-cli   # → target/release/paged

# Data Merge runs in the Node command line over the paged.data module
bun install
moon run data:wasm      # paged.data's engine
moon run data:duckdb    # its query engine, DuckDB-WASM
```

In the steps below, `paged` is that binary and `paged-node` is
`bun src/bin.ts` run in `apps/cli`, where the paged.data module resolves. The
published [`@paged-media/paged`](/docs/paged/cli/npm) package carries the same Node
command without paged.data, so it exports (PDF/X-4 too, from 0.74.2:
`--pdf-standard pdfx4 --cmyk-profile <file.icc>`) but does not merge.

### 2. Make the template

A template is any IDML whose text frames hold `<<field>>` placeholders, the form
InDesign's Data Merge uses. This script makes one on a blank A4 page:

```js title="make-template.js"
const page = JSON.parse(paged.pages())[0].selfId;
const fields = [
  [[72, 72, 120, 400], '<<name>>'],
  [[124, 72, 150, 400], 'SKU <<sku>>'],
  [[154, 72, 180, 400], '<<price>> EUR'],
];
for (const [bounds, text] of fields) {
  paged.insertTextFrame(page, bounds);
  const stories = JSON.parse(paged.stories());
  paged.insertText(stories[stories.length - 1].selfId, 0, text);
}
```

```bash
paged new --size a4 --format idml -o blank.idml
paged script blank.idml make-template.js -o template.idml --render template.png
```

### 3. Merge the records

```csv title="products.csv"
name,sku,price
Notebook A5 dotted,NB-105,9.90
Fountain pen,FP-220,34.00
Pencil set (12),PS-012,7.50
```

```bash
paged-node merge template.idml --data products.csv --out out --format paged \
  --plugins=@paged-media/data
```

```json
{ "records": 3, "format": "paged",
  "outputs": [{ "path": "out/template-merged.paged", "pages": 3, "records": 3, "overset": [],
                 "bytes": 14953 }] }
```

`--per-record` writes one document per record instead, and
`--records-per-page multiple` lays several records on a page, rows or columns first.

### 4. Export PDF/X-4

PDF/X-4 needs an output intent, so give the press's CMYK profile:

```bash
paged export out/template-merged.paged --standard pdfx4 \
  --cmyk-profile press.icc --output-condition "Your press condition" -o catalogue.pdf
```

The result is a three-page PDF/X-4 with the profile as its output intent and the
text as real, embedded text.

### The same job over HTTP

`paged engine-serve` keeps no state: each call brings the document, an optional
script and the CMYK profile, and asks for a rendered page and the PDF/X-4 back.
Here a script fills the template's three fields for one record:

```js title="fill.js"
const record = { name: 'Desk lamp', sku: 'DL-300', price: '49.00' };
const lines = [record.name, 'SKU ' + record.sku, record.price + ' EUR'];
JSON.parse(paged.stories()).forEach((story, i) => {
  paged.deleteRange(story.selfId, 0, story.characterCount);
  paged.insertText(story.selfId, 0, lines[i]);
});
console.log('filled', lines.length, 'fields');
```

```bash
paged engine-serve --port 8787 --workers 4 &

jq -n --rawfile script fill.js --arg file "$(base64 -i template.idml)" \
  --arg icc "$(base64 -i press.icc)" \
  '{file: $file, script: $script, cmykProfile: $icc,
    render: {page: 1, dpi: 72},
    export: {format: "pdf", pdf: {standard: "pdfx4"}}}' > call.json
curl -s -X POST localhost:8787/run -H 'content-type: application/json' \
  --data-binary @call.json > reply.json

jq '{output, error}' reply.json      # { "output": ["[log] filled 3 fields"], "error": null }
jq -r .file reply.json | base64 -d > lamp.pdf
jq -r .png  reply.json | base64 -d > lamp.png
```

`export` also takes `true` (the `.paged`), a format name (`paged`, `pdf`, `idml`) or
a list of these; a list answers `files: [{format, file}]` in order. A
`cmykProfile` that is not an ICC CMYK profile is answered 400 with a JSON error,
and a server started with such a `--cmyk-profile` refuses to start.

Each call runs on an engine of its own. `--workers` calls run at once (default:
the machine's parallelism), up to `--queue` more wait (default 64), and one more is
answered 503 straight away. Any instance can answer any call, so more throughput
is more instances behind a load balancer.

<Callout type="info">
Text a script adds to a document that had none, and the check on `cmykProfile`,
were fixed on main after v0.74.2. Built from v0.74.2, such text comes back
without a font and an empty profile gives a broken output intent.
</Callout>

## What to check before you move a workflow

- **Fonts.** The bundled face is a fallback, so text in families you have not
  registered is set in Inter. Register your real faces with `--fonts` (or bind
  one with `--font-family`); `--no-default-font` shows what a document is missing.
- **Linked images.** `paged` does not resolve `Links/…` files from the disk; put
  pictures in with `paged place`, or name image fields in a merge
  (`--image-field`, `--image-base`).
- **Numbers in data.** Fields arrive as written, so `9.90` stays `9.90`. To sort
  a merge numerically, cast in its query:
  `--query 'SELECT * FROM "data" ORDER BY CAST(price AS DOUBLE)'`.
- **Scripts.** Plan the port from ExtendScript as a rewrite; the
  [scripting reference](/docs/paged/scripting) lists every function and path.

## Frequently asked questions

**Is Paged a drop-in replacement for InDesign Server?**
No. It does the same kinds of job with its own command line, engine service and
JavaScript API. Templates move as IDML; scripts are rewritten.

**Does it run on Linux and in containers?**
The engine is a Rust program with no desktop dependency. paged.server's headless
lane defines a container for `paged engine-serve`; it is not built or deployed yet.

**Can it open `.indd` files?**
No. Paged reads and writes IDML, InDesign's open interchange format.

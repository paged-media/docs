The six page-item elements share one skeleton — a `Self` id, an `ItemTransform`,
a `PathGeometry`, paint attributes, an `AppliedObjectStyle` — and differ only in
a few fields. This page lists the key attributes per element and marks, from the
parser, what our renderer does with each.

The two filled shapes below — a `Rectangle` with a red fill and an `Oval` with a
blue fill — are the smallest example that exercises this page. Neither carries
text or an image; the `FillColor` alone makes them paint.

<ExampleEmbed example="filled-shapes">
  A Rectangle and an Oval, each painted by nothing but a FillColor swatch.
</ExampleEmbed>

## TextFrame

A `TextFrame` is the only member with a `ParentStory`: the story id whose
paragraphs flow into the frame. Its `ContentType` is `TextType`. Everything
else is shared.

<AttrTable
  element="TextFrame"
  rows={[
    { attr: 'ParentStory', type: 'Story id (e.g. "u10")', support: 'supported', note: 'The story whose text this frame composes. Resolved against the design map’s story list.' },
    { attr: 'ContentType', type: '"TextType"', support: 'parsed-not-rendered', note: 'Role marker. The parser infers "text" from the element name + ParentStory rather than reading this attribute.' },
    { attr: 'NextTextFrame', type: 'TextFrame id', support: 'supported', note: 'The frame that continues the story when it overflows. Drives threading.' },
    { attr: 'AppliedObjectStyle', type: 'ObjectStyle ref', support: 'supported', note: 'Real-world frames lean on this for fill / stroke far more than the per-element attributes.' },
  ]}
/>

The `TextFramePreference` child — insets, vertical justification, auto-sizing,
first baseline — has its own [reference page](/docs/frames-paths/text-frames).

## Rectangle

The workhorse. A `Rectangle` with a `FillColor` is a colour panel; with a nested
`<Image>` it is a picture frame; with neither it is an empty outline. Its
`ContentType` is `GraphicType` (or `Unassigned`).

<AttrTable
  element="Rectangle"
  rows={[
    { attr: 'PathGeometry', type: 'child element', support: 'supported', note: 'Four corner anchors for a plain rect. The parser keeps the anchors and routes non-rectangular outlines through the polygon path.' },
    { attr: 'CornerOption', type: 'enum', support: 'parsed-not-rendered', note: 'None renders square; every non-square variant (Rounded, Bevel, Inset, …) is drawn as Rounded for now. See the geometry chapter.' },
    { attr: 'StrokeAlignment', type: 'Center / Inside / Outside', support: 'supported', note: 'Inside / Outside approximated by inset/outsetting the path by half the stroke weight.' },
    { attr: 'GradientFillAngle', type: 'double (deg)', support: 'supported', note: 'Direction of a gradient fill around the frame centre. Pairs with GradientFillLength.' },
    { attr: 'FillColor / StrokeColor / StrokeWeight', type: 'see common', support: 'supported', note: 'The paint that makes the shape visible.' },
  ]}
/>

## Oval

Same fill and stroke story as `Rectangle`. Its geometry is the ellipse
*inscribed* in the path's bounding box — a square outline yields a circle, as in
the example above.

## GraphicLine

A straight stroke with no fill region. IDML stores the line implicitly: its two
endpoints are the top-left and bottom-right corners of the path's bounding box.
A `GraphicLine` has no `FillColor` field — only stroke attributes mean anything.

<AttrTable
  element="GraphicLine"
  rows={[

## Polygon

An arbitrary closed outline — charts, stars, cut-out shapes. The parser keeps
the full anchor list (and per-contour boundaries for
[compound paths](/docs/geometry-coordinates/compound-paths)).

  rows={[

## Group

A `Group` is not a shape — it is a container. Its children are the page items it
clusters, and its own `ItemTransform` composes onto each of them so the whole
cluster moves, scales, or rotates as one. It carries no fill or stroke of its
own.

**A paragraph style carries both the geometry of a paragraph and the character defaults its text starts from.**

**In short:** A `<ParagraphStyle>` sets a paragraph's alignment, indents, spacing,
hyphenation, keeps and lists, and also the font, size and colour its text uses when no
character style says otherwise. InDesign writes most of these as attributes, and a handful as
typed children of a `<Properties>` block: the font (`AppliedFont`), the parent (`BasedOn`), the
leading, the tab stops and the list settings. A paragraph refers to its style through
`AppliedParagraphStyle` on its `<ParagraphStyleRange>`.

## Where they live

Paragraph styles sit under `<RootParagraphStyleGroup>` in `Resources/Styles.xml`, optionally
inside `<ParagraphStyleGroup>` folders. Two built-ins are always present: the root
`ParagraphStyle/$ID/[No paragraph style]`, which every chain ends at, and
`ParagraphStyle/$ID/NormalParagraphStyle`, shown in InDesign as `[Basic Paragraph]`, the
style new text gets.

## Attributes and `<Properties>` children

Most paragraph-style settings are plain attributes. These are written as typed children of the
style's `<Properties>` block instead:

| Child | Type | Holds |
| --- | --- | --- |
| `<BasedOn>` | `object` (a `Self` id) or `string` (a `$ID/` root name) | the parent style |
| `<AppliedFont>` | `string` | the font family, such as `Minion Pro` |
| `<Leading>` | `unit` (points) or `enumeration` (`Auto`) | the leading |
| `<TabList>` | `list` of `record`s | the tab stops; see [drop caps and tabs](/docs/idml/typography/drop-caps-and-tabs) |
| `<BulletChar>`, `<NumberingFormat>`, `<AppliedNumberingList>`, `<BulletsCharacterStyle>`, `<NumberingCharacterStyle>` | various | list settings; see [lists, keep options and span columns](/docs/idml/typography/lists-keep-span) |
| `<SpanSplitColumnCount>` | `short` or `enumeration` (`All`) | how many columns a span or split covers |
| `<AllNestedStyles>` | `list` of `record`s | nested styles; see below |

InDesign ignores an `AppliedFont` attribute on a paragraph style; the font has to be the typed
child. The rule for `BasedOn` is the same (see [the cascade](/docs/idml/styles/the-cascade)).

> **In Paged:** the importer reads `AppliedFont`, `BasedOn` and `Leading` in either form. The
> exporter writes them as children, the way InDesign reads them.

## Character defaults

A paragraph style carries the full set of character attributes, so a run that applies no
character style still has a value for each. The common ones:

<AttrTable element="ParagraphStyle" attrs={['AppliedFont', 'FontStyle', 'PointSize', 'FillColor', 'FillTint', 'Tracking', 'Capitalization', 'Position', 'Ligatures', 'KerningMethod']} />

Their meaning is the same as on a character style; see
[character styles](/docs/idml/styles/character-styles) and the
[typography](/docs/idml/typography) chapter.

> **In Paged:** `Ligatures`, `KerningMethod` and the `OTF…` OpenType attributes are read from
> paragraph styles too, where InDesign writes them, and reach every run whose own range and
> character style leave them unset.

## Paragraph geometry

<AttrTable element="ParagraphStyle" attrs={['Justification', 'LeftIndent', 'RightIndent', 'FirstLineIndent', 'LastLineIndent', 'SpaceBefore', 'SpaceAfter']} />

`Justification` takes `LeftAlign`, `CenterAlign`, `RightAlign`, the justified modes
`LeftJustified`, `CenterJustified`, `RightJustified` and `FullyJustified`, and the
binding-relative `ToBindingSide` and `AwayFromBindingSide`. The justified modes differ in their
last line; see [justification and line-breaking](/docs/idml/typography/justification-and-linebreaking).

> **In Paged:** every value is set as InDesign sets it. The justified modes stretch every line
> but the last, which is set flush left, centred or flush right as the name says, or justified
> too for `FullyJustified`; the binding-relative values follow the side of the spine the page
> is on.

## Option families

A paragraph style carries several further families of attributes, each documented with its
topic:

- **Spacing and composition:** `Composer`, `MinimumWordSpacing` / `DesiredWordSpacing` /
  `MaximumWordSpacing`, the letter-spacing and glyph-scaling triples, `SingleWordJustification`,
  and the hyphenation family (`Hyphenation`, `HyphenateWordsLongerThan`, `HyphenateAfterFirst`,
  `HyphenateBeforeLast`, `HyphenateCapitalizedWords`, `HyphenateLadderLimit`,
  `HyphenationZone`, …). See [justification and line-breaking](/docs/idml/typography/justification-and-linebreaking)
  and [composer and OpenType features](/docs/idml/typography/composer-and-opentype).
- **Drop caps and tabs:** `DropCapCharacters`, `DropCapLines`, `DropcapDetail` and the
  `<TabList>`. See [drop caps and tabs](/docs/idml/typography/drop-caps-and-tabs).
- **Lists, keeps and columns:** `BulletsAndNumberingListType`, `NumberingExpression` and the
  list children; `KeepLinesTogether`, `KeepAllLinesTogether`, `KeepFirstLines`,
  `KeepLastLines`, `KeepWithNext`, `StartParagraph`; `SpanColumnType` and its companions. See
  [lists, keep options and span columns](/docs/idml/typography/lists-keep-span).
- **Rules, shading and borders:** `RuleAbove…` and `RuleBelow…` (on, colour, tint, weight,
  offset, indents, width), `ParagraphShading…` and `ParagraphBorder…` (on, colour, tint,
  weight, offsets, per-corner options).

- **CJK composition:** `KinsokuSet`, `KinsokuType`, `MojikumiTable` / `Mojikumi`.

## Nested styles

A nested style applies a character style to the start of each paragraph, up to a delimiter: the
first word, the first tab, everything before a colon. InDesign writes a paragraph style's
nested styles as `<Properties><AllNestedStyles type="list">`, one `record` per nested style,
each naming the character style, the delimiter, how many times it repeats and whether the
delimiter itself is included.

> **In Paged:** the `<AllNestedStyles>` list InDesign writes is read, on a paragraph style and on
> a `<ParagraphStyleRange>`, and nested styles are applied with InDesign's delimiter rules,
> including `Repetition` and `Inclusive`. A nested style sits under a character style the run
> applies itself and over the paragraph style. Line and GREP styles (`<AllLineStyles>`,
> `<AllGREPStyles>`) are read and saved back but not applied yet. The `<NestedStyle>` element
> earlier Paged versions wrote is still read, and saving rewrites it into InDesign's list.
> <SupportBadge feature="stories-text.nested-styles" />

## `NextStyle`

`NextStyle` names the paragraph style InDesign gives the next paragraph when the user presses
Return at the end of this one. It is an authoring setting: it changes nothing about how existing
text looks. A heading style typically has `NextStyle` set to the body style; a body style
usually points at itself.

> **In Paged:** `NextStyle` is read, can be set, and survives a save. It does not affect
> rendering. <SupportBadge feature="styles.next-style-overrides" />

## Frequently asked questions

**How do I set a paragraph style's font in IDML?**
With a typed child: `<Properties><AppliedFont type="string">Minion Pro</AppliedFont></Properties>`,
plus `FontStyle="Bold"` as an attribute for the face. InDesign ignores an `AppliedFont` attribute
on the style.

**What is the difference between a paragraph style and a character style?**
A paragraph style sets whole-paragraph properties (alignment, indents, spacing, keeps, lists)
and the character defaults the paragraph's text starts from. A
[character style](/docs/idml/styles/character-styles) applies to a run inside a paragraph and
usually sets only the few attributes that differ.

**What is `[Basic Paragraph]`?**
The built-in style InDesign applies to new text. Its id is
`ParagraphStyle/$ID/NormalParagraphStyle`. It is an ordinary, editable style based on the
`[No paragraph style]` root.

**Does `NextStyle` change how a document renders?**
No. It only tells InDesign which style to apply to a new paragraph typed after this one.

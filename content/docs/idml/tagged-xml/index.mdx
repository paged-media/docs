**Tagged XML is a second view of an IDML document: the same content organised as a tree of user-defined tags instead of as pages.**

**In short:** In InDesign an author can tag content with their own XML structure:
wrap a heading and its body in a `chapter` element, mark a price as `price`. That
structure is independent of the layout, and IDML records it apart from the stories and
spreads. The tag names are `XMLTag` elements in `XML/Tags.xml`; the tree of tagged
elements lives in `XML/BackingStory.xml`, rooted in an `XmlStory`. Both parts are in
every package, because every document has at least a root element, even when nobody
tagged anything.

## What the layer is

The same heading can be an `h1` in the document's XML and a "Heading 1" paragraph in the
layout at the same time: two labels on one piece of content. Tagging does not move or
copy the text. The XML tree refers to placed content, so the tree and the stories
describe the same characters from two directions. Content that has been tagged but not
yet placed on a page waits in the backing story.

The layer is spread over these parts:

| Part | Holds | In the census |
|---|---|---|
| `XML/Tags.xml` | the tag names a document defines, one `XMLTag` each | all 305 documents |
| `XML/BackingStory.xml` | the `XmlStory` with the tree of `XMLElement`s | all 305 documents |
| `XML/Mapping.xml` | maps between tags and styles | only generated files |

The design map references `Tags.xml` and `BackingStory.xml` with `idPkg:Tags` and
`idPkg:BackingStory`. An untagged InDesign document carries one tag, `Root`, and one
`XMLElement` that applies it.

## Why a reader cares

If you **generate** IDML for a publishing pipeline, the tagged structure is how
downstream tools find content by meaning rather than by position. If you **render or
extract** IDML, it is safe to set aside: nothing in the XML layer changes where a glyph
lands, and the text you need is in the [stories](/docs/idml/package-anatomy/content-parts).
If you **edit and save** IDML, keep the XML parts: they are part of the document, and a
file without them is not the document InDesign wrote.

## Frequently asked questions

**What is the tagged-XML layer in IDML?**
A tree of user-defined XML tags drawn over a document's text and frames, stored in
`XML/Tags.xml` and `XML/BackingStory.xml`. It describes the content by meaning, beside
the layout that places it.

**Is the XML layer in every IDML file?**
`Tags.xml` and `BackingStory.xml` are: an untagged document still has a `Root` tag and a
root element. `Mapping.xml` appears only in some generated files.

**Do I need the XML layer to render a document?**
No. Layout comes from the spreads, stories and styles. The XML layer labels that content
without changing it.

**Can I delete the `XML/` parts?**
Not safely. The design map references them, and the tagged structure is part of the
document an author made. Keep them when you save.
